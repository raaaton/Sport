# Rest Live Activity timer layout and controls implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. This run is inline; do not delegate.

**Goal:** Make Sport's rest Live Activity use a stable, compact, Timer-like native layout and let Pause/Resume and Stop update the same persisted rest timer from the expanded Island and Lock Screen.

**Architecture:** Keep Expo Widgets as the Live Activity owner and keep `Documents/SQLite/sport.db` as the only source of truth. A `LiveActivityIntent` will validate the activity/timer identity, apply an existing rest transition under a native SQLite transaction, then update or end that exact ActivityKit activity. On foreground, the workout screen reloads the persisted timer so its UI catches up with native actions.

**Tech Stack:** Expo SDK 57 (`expo-widgets` 57.0.22, `expo-sqlite`), React Native/TypeScript, SwiftUI, ActivityKit, App Intents, SQLite.

**Spec:** `docs/superpowers/specs/2026-10-04-rest-live-activity-design.md`

**Status:** In progress (user approved inline execution).

## Global Constraints

- iOS 16.4 remains the deployment floor; Live Activity controls are available on iOS 17 and later, with read-only presentation on iOS 16.4.
- Keep `Documents/SQLite/sport.db` as the source of truth; do not relocate it or add a schema migration.
- Keep the feature local and offline; do not add backend, push, analytics, database sharing, or dependencies.
- Stop means the existing `skip` transition (`Passer le repos`), not workout cancellation.
- Pause/Resume and Stop controls appear in the expanded Dynamic Island and Lock Screen on iOS 17 and later.
- Keep the compact leading content to a small blue timer symbol plus `Rest`, with the remaining time trailing; do not force region widths or add extra labels.
- Use system Dynamic Island margins and the adaptive Lock Screen surface; use white text and restrained blue accents without a full blue tint.
- Use one native SwiftUI timer `Text` path for running and paused states; do not replace it with a separately formatted paused label.

## Review Focus

- Stale, mismatched, missing, or malformed activity/timer data must not mutate another rest row or claim an active rest; Tasks 1 and 3 cover the view fallback and identity guard, and Task 2 covers missing IDs.
- A repeated Pause request must remain paused instead of toggling back to running; Task 2 tests idempotent desired-state actions.
- A Pause racing the deadline must persist `finished` and end the stale activity; Task 2 tests deadline handling and Task 3 verifies terminal activities end.
- A SQLite open/write failure must leave ActivityKit content untouched; Task 3 updates ActivityKit only after the store returns successfully.
- iOS 16.4 must compile and render without interactive controls; Task 3 keeps button construction behind the iOS 17 availability check and the iOS build compiles the generated target.

## Objective

Repair the clipped and inconsistent rest Live Activity, add native Pause/Resume and Stop controls to expanded Dynamic Island and Lock Screen on supported iOS, keep the workout model and existing SQLite schema unchanged, and synchronize the workout UI when Sport returns from suspension.

## Context and decisions

- `scripts/apply-sport-native-live-activity-layout.mjs` patches Expo's generated `WidgetLiveActivity.swift`. It currently forces two-point compact margins, changes the leading label between `REST` and `PAUSE`, renders a static paused string, and uses `R` in the minimal presentation.
- `src/features/workout/domain/restTimerMachine.ts` defines the canonical `pause`, `resume`, `tick`, and `skip` transitions. The native store must preserve those persisted-state semantics, including expiry at the action time.
- Expo's existing `LiveActivityUserInteraction` only posts an Expo notification. It does not durably change the SQLite row when the React Native UI is suspended. The custom `LiveActivityIntent` must update SQLite directly in Sport's process; no App Group copy of the database is needed.
- The existing native source is generated by `expo-widgets` 57.0.22 during prebuild. Keep all patches version-guarded and idempotent, and assert the resulting files in CI.
- The user selected an isolated worktree, but the sandbox blocked writes to `.git`; implementation stays in the current checkout. Preserve the unrelated, pre-existing untracked `.agents/` directory.
