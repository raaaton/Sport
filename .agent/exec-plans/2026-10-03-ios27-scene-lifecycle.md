# ExecPlan: iOS 27 scene lifecycle launch crash

## Objective

Fix Sport's immediate launch crash on iOS 27 when built with the iOS 27 SDK. Preserve Expo Router, keep native lifecycle code generated by Expo, and validate the generated scene configuration locally. Also complete the user's adjacent request by keeping the simplified GitHub workflow and publishing normal Releases.

## Diagnosis

The supplied Sport `.ips` report shows `EXC_BREAKPOINT` / `SIGTRAP` on the main thread during UIKit scene creation. Its crashing symbol is `___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption_block_invoke`. The installed app is `com.raaaton.sport.HCWJFQ48WN`, launched on iOS 27.2 beta. The generated Expo SDK 57 app currently uses the legacy application lifecycle and emits no `UIApplicationSceneManifest`; this matches Apple's iOS 27 launch assertion for apps built with the latest SDK that don't adopt `UIScene`.

Expo SDK 57.0.23+ provides `expo-build-properties` `ios.enableSceneSupport`. Its config plugin updates the generated AppDelegate to use Expo's `ExpoAppSceneDelegate` and adds the static scene manifest. Use the SDK-compatible bundled version `~57.0.22`; do not hand-roll another Swift SceneDelegate.

## Implementation

1. Add the SDK-matched `expo-build-properties` dependency with `npx expo install` and configure `ios.enableSceneSupport: true` in `app.json`.
2. Regenerate iOS with Expo prebuild and inspect the generated AppDelegate and Info.plist. Assert the scene manifest points to `EXExpoAppSceneDelegate` and the legacy inline window/startup block is removed.
3. Keep the GitHub Actions build concise and release each successful `main` build as a normal, latest GitHub Release; do not upload a duplicate Actions artifact or mark it prerelease.
4. Run TypeScript, lint, tests, Expo dependency checks, iOS JS export, prebuild, static scene assertions, workflow YAML/Bash checks, and `git diff --check`.
