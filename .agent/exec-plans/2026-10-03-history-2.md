# ExecPlan: History 2.0

## Objective and scope

Turn History into a readable record of completed workouts and exercise performances. Add a session view, exercise filter with simple performance evolution, and complete manual create/edit/delete flows persisted to SQLite. Manual entries must behave like real completed workouts and feed the existing latest-performance/progression queries. Keep the existing workout flow, timer, Today, tabs, and progression rules unchanged.

## Context and decisions

- Current schema v2 already stores date-only `workouts.date`, completed/status state, ordered exercises, per-set reps or duration and weight, and exercise-level decimal Feeling. `workout_exercises.workout_id` cascades to exercises, and `workout_sets.workout_exercise_id` cascades to sets. Deleting one workout row therefore removes its dependent performance rows; the existing foreign-key setting is enabled by the database adapter.
- Add a v3 history index for completed workout date ordering. Keep session dates as validated `YYYY-MM-DD` calendar dates, independent of timezone conversion. Manual timestamps use noon UTC on the selected calendar date so legacy timestamp ordering remains stable; user-facing ordering and latest-performance selection use the persisted calendar date first.
- Manual create/edit will validate every completed exercise and its ordered sets using the same numeric constraints as workout entry: exactly the target set count, positive integer reps/duration matching tracking type, optional finite nonnegative decimal load, and exercise Feeling from 0 through 10. A date may be historical or today; future dates are rejected because this flow records past sessions.
- Edit updates the existing workout row and replaces its child exercise/set rows inside one transaction. It does not create a second workout. Delete removes the workout in a transaction and relies on the already defined foreign-key cascade; tests will verify no orphan rows remain.
- Manual completed workouts have `schedule_id = NULL`; they do not interfere with the planned workout lock for a day. The existing progression engine remains derived: its existing latest-performance query will select manual rows according to the actual session date, and edits/deletes will naturally change that result.
- History uses a native stack detail/form flow, grouped system-like rows, the shared `AppScreen`/`DynamicScrollView`, and the existing theme/SF Symbol/haptic primitives. No UI, state-management, or date-picker dependency is added. Dates are entered as ISO calendar dates and validated before save.
- Main History has two modes: completed sessions and exercise performances. Exercise mode shows reverse-chronological records and a restrained set of simple data summaries for reps/duration, load, and Feeling; no arbitrary scores or chart library.

## Implementation notes

- Initial inspection found History is still a compact session list. The current completed-workout and latest-performance queries sort by timestamps rather than the user-entered calendar date, which would misorder backfilled sessions; both must use the stored `date` first.
- The existing worktree contains many unrelated uncommitted/untracked foundation and feature files from earlier stages. This plan and subsequent commits will stage only files changed for History 2.0; no broad cleanup or unrelated staging is included.
- Added schema v3's date/status history index. SQLite already cascades from workouts to workout exercises and from exercises to sets, so delete removes all associated rows without a new cascade migration.
- Added typed complete-workout payload validation and transactional create/update/delete APIs. Manual timestamps use noon UTC on the chosen ISO calendar date; ordered queries now use the stored workout date first.
- Added SQLite integration coverage for date validation/order, session and exercise filtering, decimal feeling/load, manual performance/progression refresh after edit, deletion cascades, and time-based values. All tests, TypeScript, ESLint, and diff whitespace checks pass for this layer.
